1.2 Existing architecture review

Solid foundation (keep)
  • Next.js 15 + TypeScript + Prisma 6 + MySQL; one app for all companies.
  • Every company record carries workspaceId; every query filters by it; linked ids are verified; uniqueness per company. Tested for isolation in every suite.
  • Signed session cookie; user re-loaded on every request; roles enforced in server actions, not only in the UI.
  • Wallet ledger with atomic balance updates and a once-per-call charge guard.
  • India-first: IST everywhere, ₹ formatting, Indian number cleaning, DND flag.
Gaps that block the v4 vision
  • No background jobs: nothing runs on a schedule, so campaigns and callbacks never execute.
  • No inbound API: no webhooks, no API keys, no signature checks, so no outside source can send leads.
  • No secrets vault: provider keys and OAuth tokens need encrypted storage.
  • No file storage for recordings and knowledge documents; no search index for knowledge.
  • No outbound email: blocks invites, password reset, email follow-ups.
  • No audit log, no login rate limiting, no provider/usage cost records.
  • Lead model too thin (no email, company, source, budget); pipeline stages fixed.

1.3 Missing functionality (summary)

  1. Platform plumbing: job queue + worker processes, public API and webhooks, encrypted credentials, file storage, email service, audit log, rate limiting.
  2. Lead Source Integration Hub (all connectors, hub dashboard, processing pipeline with merge and attribution).
  3. Prospect discovery (data sources, review/approve, compliance gate, deletion).
  4. CRM depth: richer lead fields, custom pipelines, scoring, AI-written fields with change history, meetings.
  5. Voice engine (inbound/outbound, browser test, SIP), provider registry, plan-based model access, knowledge documents.
  6. Orchestration & automation: campaign runner, callback runner, next-action engine, workflows, approvals, escalation.
  7. Communication hub: WhatsApp, email, SMS, unified history; meetings with calendars.
  8. Conversion & onboarding; Team & Settings; Super Admin; cost lines + reports; payments.

1.5 Backend API requirements

Public (outside world → Voxura)
  • POST /api/hooks/meta: Meta leadgen webhook (verify token + X-Hub-Signature-256).
  • POST /api/hooks/google-ads/:key: Google lead form webhook (per-form key).
  • POST /api/hooks/in/:endpointId: generic webhook for websites, WordPress, Zapier, Make (HMAC signature or secret).
  • POST /api/v1/leads, GET /api/v1/leads/:id: REST API with company API keys, rate-limited.
  • POST /api/hooks/voice/*, /whatsapp, /email, /payments: provider callbacks.
  • Every inbound event is stored first (idempotency key), then processed by a job, so retries never duplicate leads.
Internal (app + workers)
  • OAuth connect/callback for Meta, Google, calendars; token refresh jobs.
  • Pollers for sources without webhooks (IndiaMART API, mailbox parsing, Sheets).
  • Lead processing job: validate → normalise → dedupe/merge → attribute → assign agent → next action.
  • Orchestrator: event → context → AI recommendation → policy check → job.
  • Campaign and callback runners; message sender; meeting reminder jobs.
  • Billing: usage → cost lines → customer charge → wallet (exactly once).
  • Admin APIs for every Super Admin screen, with audit writes in the same transaction.

1.8 Development dependencies and testing

New building blocks
  • Job queue (Redis + BullMQ) with separate worker processes; jobs are idempotent and retried safely.
  • Python voice worker on LiveKit Agents (one process per call, scaled by lines).
  • Secrets: AES-GCM encryption for tokens and keys with a master key outside the database.
  • Search index for knowledge documents (embeddings).
  • Hosting: VPS (web + workers + Redis + MySQL) in India, HTTPS, backups, monitoring.
Testing requirements
  • Keep the 285 end-to-end checks green on every change; add a suite per module.
  • Webhook tests with signed sample payloads (valid, bad signature, replay, duplicate).
  • Tenancy tests for every new table and API (company B can never read or write company A).
  • Billing tests: each usage event charged exactly once under retries and concurrency.
  • Orchestrator tests: AI suggestions that break a rule (DND, hours, wallet, discount) are always refused.
  • Provider sandboxes (Meta test leads, Razorpay test mode), voice quality checks in Hindi/Hinglish, load test for concurrent calls.

3.3 Security

  • OAuth tokens, API keys and provider secrets encrypted (AES-GCM) with a master key outside the database; secrets shown once.
  • Every webhook verified (Meta X-Hub-Signature-256, HMAC for our webhooks), replay-protected, rate-limited.
  • Company isolation enforced in every query and every job (jobs carry workspaceId and re-check it).
  • The AI has no direct database or payment access: it can only return suggestions that the platform checks and executes.
  • Audit log for admin and money actions; activity log per company; support access only with consent.

Decisions needed before development

  4. Prospect data provider and budget (licensed B2B data), plus legal review of its use.

  6. Approval limits: AI discount limit; who confirms payments and conversion.
